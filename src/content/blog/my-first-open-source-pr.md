## The Fear of Being Wrong

I had used Git before. I had forked repos. But opening a pull request (PR) on a project with hundreds of stars? Terrifying.

What if my code was ugly? What if I misunderstood the issue? What if someone laughed?

## Picking the Wrong First Issue (On Purpose)

I avoided “good first issues” with simple typos. Instead, I picked a documentation improvement that required understanding the project’s architecture. Harder. Slower. But I would learn more.

The issue: update a setup guide for Ubuntu 24.04.

## The 3-Week Timeline

- **Week 1** – Read the codebase. Got lost. Took notes on paper.
- **Week 2** – Made changes locally. Ran tests. Failed. Fixed. Failed again. Realized I needed to update two files, not one.
- **Week 3** – Opened the PR. A maintainer commented within 4 hours. Small formatting requests. I fixed them. Then… green checkmarks. Merge.

I stared at the “merged” message for ten minutes.

## What That PR Taught Me

- Open source is not a test. It’s collaboration.
- Maintainers want you to succeed (most are kind).
- The hardest part is starting.

Now I help new contributors find their first issues. The fear never goes away. But neither do I.
